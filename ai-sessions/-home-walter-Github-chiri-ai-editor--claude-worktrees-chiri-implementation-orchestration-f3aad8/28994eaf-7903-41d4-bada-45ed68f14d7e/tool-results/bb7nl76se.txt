# 0002. Structured model output; the app owns the anchors

- Status: Accepted (2026-10-28)
- Source: planning session, Q10, Q39

## Context

What can go wrong with a model's answer here:

| Failure | Plain text | Structured JSON |
|---|---|---|
| Wrapper chatter ("Sure! Here's…", code fences) | happens, needs cleaning | gone, the schema enforces the shape |
| Changes beyond the Instruction | happens | happens equally |
| Invented content | happens | happens equally |
| Wrong location (quotes text that doesn't exist) | impossible, the app knows the range | **new risk**, if the model picks the location |

The diff itself guards against rows 2 and 3: every change is visible before Accept. Structure removes row 1 and makes the answer checkable, but can create row 4.

## Decision

- **Strict structured outputs:** `structured_outputs` with OpenRouter `provider.require_parameters: true`, so only providers that support it are used. One zod schema per shape is both the validator and the source of the JSON Schema.
- **Target requests and Refine:** the app already knows the range. The model returns `{ replacement, rationale }`.
- **Review pass:** the app numbers Blocks (`p1`, `p2`, …) before sending. The model returns `{ edits: [{ blockId, replacement, rationale }] }` and never copies text to say where. A Block is a top-level node of the Markdown syntax tree; a whole list is one Block.
- **Wire shape with AI SDK `Output.array`:** the SDK owns the wrapper, so the Review pass wire shape is `{ elements: [...] }`; each element is `{ blockId, replacement, rationale }`.
- **App-side validation:** drop an item when `replacement` equals the original or `blockId` is unknown. On invalid output, retry once silently, then show an error card.

## Consequences

- No chatter, a Rationale for every change, and answers the app can check.
- Review pass granularity is one Block: two changes in one paragraph become one Suggestion, and a long list is a single Suggestion.
- Format constraints may slightly lower writing quality ("Let Me Speak Freely?", 2024). The Bake-off watches for it ([0010](0010-model-bakeoff.md)).

## Alternatives considered

- **Plain-text Replacement for Target requests:** simplest, but no Rationale and no validation.
- **Quote-anchored edits `{ quote, replacement }` everywhere:** uniform, but a one-character slip in `quote` drops the edit, even where the app already knew the range.
- **Character offsets:** models are bad at counting characters.
- **Blank-line splitting for Blocks:** breaks on lists without blank lines and on code blocks that contain empty lines.
# 0004. User-triggered AI, plus an on-demand Review pass

- Status: Accepted (2026-10-28)
- Source: planning session, Q5, Q12, Q28

## Context

"The user is always in control", but the AI should feel like a co-author, not something that completes the whole Document.

## Decision

- **The AI acts only when asked.**
- **Selection bubble:** Quick actions (Shorter, Clearer, More formal, Fix grammar) plus a free-text "Ask AI…" field. `Cmd/Ctrl+K` opens the same field. With no selection, the Target is the Block under the cursor.
- **Review pass:** a toolbar button with an optional Focus. Without Focus, the AI looks at clarity, concision, grammar and tone consistency. It returns at most 6 Suggestions, most important first. It skips code blocks and Blocks that already have an open Suggestion.
- **No slash commands, no proactive hints.**
- Many Suggestions can be open at once from day one.

## Consequences

- Predictable, cheap, and the user is in control.
- The Review pass gives the "colleague marking up my draft" feeling without ambient noise.
- The 6-Suggestion cap leaves issues untouched in long, rough Documents. A wall of red and green would read as "the AI rewrote everything".

## Alternatives considered

- **Proactive hints on idle:** the strongest co-author feel, but it burns tokens under a US$5 cap, is noisy, and is hard to tune.
- **Slash commands:** they pull toward "generate at cursor", which is close to completing the Document.
- **Free-text only, no Quick actions:** less discoverable. Reviewers would have to invent what to ask.
# 0007. Suggestion lifecycle

- Status: Accepted (2026-10-28)
- Source: planning session, Q13, Q19, Q20, Q21, Q22, Q25, Q32

## Context

Suggestions are overlays ([0001](0001-inline-overlay-suggestions.md)) and the user keeps typing while they are open or in flight.

## Decision

- **Edits outside a Suggestion:** its range is mapped through the change (CodeMirror `ChangeSet` mapping).
- **Edits inside an open Suggestion, or inside an in-flight request's Target:** Discard it, with a discreet notice ("Suggestion discarded: the text changed").
- **Overlaps:** a new request over an open Suggestion replaces it, so the last one wins. The Review pass skips Blocks with open Suggestions.
- **Active Suggestion:** shows the Accept / Reject / Refine toolbar. Its Rationale shows on hover, and when the text cursor is inside it (keyboard users can't hover). Other Suggestions show only the inline diff.
- **Keys, with the cursor inside a Suggestion:** `Cmd/Ctrl+Enter` Accepts, `Esc` Rejects. Accept is a normal edit, so `Cmd+Z` undoes it. Reject is not undoable in v1. A Review pass also offers Accept all and Reject all.
- **Refine:** a follow-up Instruction on the Active Suggestion. The new Replacement replaces the old one in place. The diff is always against the original text. History stays in memory, with no version arrows in v1.
- **Persistence:** only the Document text goes to `localStorage`. Open Suggestions are lost on reload.
- **Failures:**
  - Missing key: banner ([0005](0005-local-only-vite-proxy.md)).
  - Failed call (network, `402` out of credit, `429`): the Suggestion becomes an error card with Retry. `402` gets its own message.
  - Invalid output: one silent retry, then the error card.
  - Timeout: 30 s.

## Consequences

- Simple, honest rules. A user who bumps into a Suggestion loses it, and can ask again.
- An accidental `Esc` loses a Suggestion. An undoable Reject is in the backlog.

## Alternatives considered

- **Keep a stale Suggestion with "regenerate":** an extra state, and an old diff can't be drawn over changed text.
- **Lock the range while a Suggestion is open:** takes control away from the user.
- **Block new requests until the old Suggestion is resolved:** friction.
- **Allow overlapping Suggestions:** accepting one breaks the other.
- **Rationale always visible, or in a side panel:** the side panel drifts toward the chatbot sidebar.
# 0008. Stream only where each piece arrives validated

- Status: Accepted (2026-10-28)
- Source: planning session, Q24, Q31

## Context

Streaming has three costs here: parsing half-finished JSON, a diff that jitters while text arrives (not-yet-rewritten original text shows as deleted), and showing text before it is validated.

AI SDK v7, verified in its docs on 2026-10-28:
- With `Output.object`, `partialOutputStream` yields partial objects that "cannot be validated against your provided schema". Only the final output is validated.
- With `Output.array`, `elementStream` yields each element "complete and validated against your element schema".

## Decision

- **Review pass:** stream with `Output.array` and `elementStream`. Each Suggestion appears once it is schema-validated by the SDK and checked by the app (`blockId` exists, Replacement differs from the original).
- **Target requests and Refine:** not streamed. `Output.object`, validated before anything is shown.
- **Reopen rule:** if the chosen model's median latency for Target requests is above ~3 s, add a Draft preview: streamed text without a diff that turns into the diff once validated.

## Consequences

- The slowest call, the Review pass, shows its first Suggestion early, with no validation trade-off.
- Target requests stay simple: one state, validated before display.
- The Draft preview sits in the backlog behind a measurable rule.

## Alternatives considered

- **No streaming at all:** simplest, but the Review pass waits for all 6 Suggestions.
- **Stream everything, including a Draft for Target requests:** matches the challenge's "live preview" idea, but adds a visual state and a Draft that can fail validation and vanish.
## Notes for the choice

Written by hand after the run. The tables above and below are generated.

- **Timeout.** The runs used 60 s for the Review pass. After the run it was set back to 30 s, as [ADR 0007](adr/0007-suggestion-lifecycle.md) says; every model except `qwen/qwen3.8-flash` finished its Review pass in under 8 s.
- **Validity.** All 9 models returned schema-valid output on the first try in every request: 0 retries and 0 edits dropped by the app checks, in all three runs. The strict JSON schema with `require_parameters: true` held for every candidate.
- **Latency.** Six models have a median Target request under ~3 s in all three runs (see the table below). `google/gemini-3.8-flash` (3.8 to 5.4 s), `google/gemini-4-argon` (5.0 to 10.3 s) and `qwen/qwen3.8-flash` (11 to 15 s) are over the ADR 0008 line, so picking one of them reopens the Draft preview.

### Why three runs

1. **Run 1.** The Rationale rule said "the language of the text you receive, not the language of these rules". Four models (GLM, DeepSeek, both small Gemini) answered in French, German or Spanish on an English Document, probably because the negative wording pushes a model away from English.
2. **Run 2.** The rule was reworded as a positive anchor ("the same language as the Document text") and the Rationale schema field says "in the same language as the replacement". The anchor sentence was added at the end of the Review instructions, and `anthropic/claude-sonnet-5.5` and `z-ai/glm-5.3-flash` started returning a single junk edit (`replacement: "x"`, or the last paragraph replaced by "Thank you!"). Removing the sentence restored Sonnet in 2 of 2 checks.
3. **Run 3.** The sentence now sits after the Blocks, at the very end of the Review prompt. Sonnet, GLM and the rest behave. This is the prompt the app ships.

The junk edit passed every app check (known Block, changed, not empty). A guard against a Replacement that is a tiny fraction of the original is worth considering in slice 5.
